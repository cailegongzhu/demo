一次完整的提交流程

照着做一遍就会了
查看当前状态

git status —— 随时知道哪些文件被改了、哪些已暂存。

暂存改动

git add . 把当前目录所有改动放进暂存区（也可指定单个文件）。

提交存档

git commit -m "说明这次改了什么" —— 写清楚、写具体，未来的你会感谢现在的你。

推送到远程

git push origin master 把本地提交同步到远程仓库，完成一次协作闭环。

4

分支：Git 最强大的地方

互不干扰地并行开发

主分支 master / main

稳定版本

始终保持可发布状态，只接收经过验证的合并。

功能分支 feature/xxx

开发中

从主分支切出，开发完再 merge 回去，互不影响。

分支三连： git checkout -b feature/login 新建并切换 → 开发并提交 → git checkout master 切回 → git merge feature/login 合并。
5

新手最容易困惑的点

commit 之后想改怎么办？

不要害怕「写错」。改完再 add + commit 一次即可；只有最后一次提交可以用 git commit --amend 修改。

add 错了想撤销？

git restore --staged 文件名 把它从暂存区移回工作区，文件本身不会丢。

push 被拒绝（rejected）？

说明远程有本地没有的提交。先 git pull 合并远程改动，再 push。
