# Git 上手说明（配合 index.html 使用）

这份说明是给「刚开始学全栈、正在学 Git」的你写的。目标不是背命令，而是**在你自己的这个仓库里，把 Git 的完整流程亲手走一遍**。

> 好消息：当前目录 `D:/code/demo` 已经是一个 Git 仓库（`git init` 已完成），而且**还没有任何提交**。这正是练习的最佳起点。

---

## 一、先理解一件事：Git 在管什么

Git 就是一个「存档系统」。它把你的文件状态一次次拍成快照存起来，随时可以回到过去、看看改了什么、和别人协作。

记住四个区域（网页第 1 节有图）：

```
工作区  --git add-->  暂存区  --git commit-->  本地仓库  --git push-->  远程仓库
```

- **工作区**：你平时改的文件。
- **暂存区**：筛选出来的、这次要一起存的文件。
- **本地仓库**：commit 之后，快照存进 `.git` 文件夹。
- **远程仓库**：GitHub / Gitee 上的备份与协作空间。

## 二、第一次使用：先告诉 Git 你是谁

打开终端，进入本目录：

```bash
cd D:/code/demo
```

设置身份（只需设置一次，全局生效）：

```bash
git config --global user.name "你的名字"
git config --global user.email "you@example.com"
```

检查一下有没有生效：

```bash
git config --global --list
```

## 三、跟着做：你的第一个 commit

按顺序在终端里敲下面每一行，观察输出。

**1. 看看当前状态**

```bash
git status
```

你会看到 `index.html` 和 `使用说明.md` 是红色的未跟踪文件（untracked）。

**2. 暂存文件**

```bash
git add index.html 使用说明.md
```

再 `git status`，它们变绿了——说明已进入暂存区。

**3. 提交（存档）**

```bash
git commit -m "初识 Git：添加学习网页和使用说明"
```

看到 `1 file changed...` / `2 files changed...` 之类的输出，就成功了。这一步就是你的第一个版本快照 🎉

**4. 查看历史**

```bash
git log --oneline
```

能看到刚才那条提交记录，前面是一串短哈希值。

## 四、练习「修改 → 再提交」的循环

1. 用编辑器打开 `index.html`，随便改一句文字并保存。
2. `git status` —— 会显示文件被修改（modified）。
3. `git diff` —— 看看具体改了哪几行。
4. `git add index.html`
5. `git commit -m "修改首页标题文案"`
6. `git log --oneline` —— 现在有两条记录了。

这就是 Git 日常 90% 的工作：**改 → add → commit**。

## 五、练习分支（Git 的精髓）

```bash
git checkout -b feature/test      # 新建并切换到分支 feature/test
```

现在你在一个独立的分支上。改点东西，然后 add + commit。

```bash
git checkout master               # 切回主分支，刚改的内容"消失"了？其实在另一个分支上
git log --oneline                 # 主分支只有之前的提交
git merge feature/test            # 把功能分支的改动合并回来
git log --oneline                 # 现在主分支也有那条记录了
```

分支的意义：**在同一份代码上并行做事，互不干扰，成熟后再合并。**

## 六、连接远程仓库（GitHub / Gitee）

本地玩熟了，再同步到网上：

```bash
# 1. 在 GitHub / Gitee 网页上新建一个空仓库，复制它的地址
# 2. 关联远程仓库（origin 是惯用别名）
git remote add origin <你的仓库地址>

# 3. 推送（第一次加 -u 建立追踪关系）
git push -u origin master

# 4. 以后同步远程改动
git pull
```

如果 push 被拒绝（rejected），先 `git pull` 把远程的新提交合进来再 push。

## 七、常用命令清单（速查）

| 场景 | 命令 |
| --- | --- |
| 初始化 | `git init` / `git clone <地址>` |
| 配置身份 | `git config --global user.name "..."` / `user.email "..."` |
| 看状态 | `git status` |
| 暂存 | `git add <文件>` / `git add .` |
| 提交 | `git commit -m "说明"` |
| 看历史 | `git log --oneline` |
| 看改动 | `git diff` |

| 丢弃改动 | `git restore <文件>`（谨慎） |
| 临时存档 | `git stash` / `git stash pop` |

## 八、给新手的 4 条真心建议

1. **多敲 `git status`。** 不确定发生了什么时，先看状态，它就是你的仪表盘。
2. **提交说明写人话。** 写"修复登录页按钮错位"，别写"更新"或"123"。
3. **小步提交。** 一个功能点一个 commit，出问题好定位、好回滚。
4. **别怕出错。** 几乎所有操作都能补救；真正不可逆的只有 `--hard` 和强推，初学阶段先别碰它们。

## 九、网页的「结构 / 样式 / 行为」分离

打开网页文件你会发现，它已经拆成了三个文件。这是前端最重要的基础习惯：

| 文件 | 负责什么 | 类比 |
| --- | --- | --- |
| `index.html` | **结构**：页面里有哪些内容 | 房子的墙和房间 |
| `style.css` | **样式**：内容长什么样 | 装修和配色 |
| `script.js` | **行为**：点击后发生什么 | 水电和开关 |

好处是：想改配色只动 CSS，想改交互只动 JS，互不干扰；多个网页还能共用同一份样式。
HTML 里通过 `<link rel="stylesheet" href="style.css">` 引入样式，通过 `<script src="script.js"></script>` 引入脚本（放在 `</body>` 前，确保 DOM 已加载）。

## 十、进阶练习：.gitignore

项目里备好了 `.gitignore` 和几个练习文件（`.env`、`.env.example`、`debug.log`）。试着在终端执行：

```bash
git status                 # 看不到被忽略的文件
git status --ignored       # 加上 --ignored 就能看到它们
git check-ignore -v .env   # 查看是哪条规则忽略了它
```

重点理解：`.env`（含密钥，被忽略）和 `.env.example`（模板，应提交）的区别——这是全栈项目最经典的套路。

## 十一、接下来学什么

Git 只是全栈的第一块砖。建议路线：

```
Git + 命令行  →  HTML/CSS/JS  →  一个前端框架(如 React/Vue)
  →  后端(Node.js/Python)  →  数据库  →  部署上线
```

你现在已经有了网页（`index.html` / `style.css` / `script.js`）和这份说明，正好可以作为练习 Git 的第一个小项目——边学边提交，就是最好的记忆方式。
